# Live run: `q:` from nvim-tree, 5 Nov 2026

**What ran:** a headless Neovim 0.12.5 with the operator's own config
(lazy.nvim, nvim-tree), the plugin's modules replaced by the `side-panels`
branch's with `dofile`, the real `claude -p` (Sonnet). **When:** about
20:50 UTC. **File:** `# Title` / `line two` / `line three`, with nvim-tree
open and focused.

## Changed since last run

The operator reported that leaving `q:` put them back in nvim-tree. A
request from there would also have described the tree to the model, and its
command would have run in the tree. This branch: the last file window
stands in for a panel (context and where the command runs), and
`require('morla').open()` for a mapping.

## Results

| check | result |
|---|---|
| `q:` typed in nvim-tree | does not open `q:`: nvim-tree maps `q` to close the tree |
| `open()` with the tree focused | moved to `n.md`, opened `q:` in insert mode |
| "delete line two" | `2d`; ran on `n.md` (`# Title` / `line three`) |
| after the run | `q:` open again over `n.md` (`stay`) |

## Findings

- In nvim-tree, `q:` cannot be typed at all; a mapping to `open()` is the
  way in from there. The `win_gotoid` prefix (ARCHITECTURE D15) covers other
  panels and is checked by `tests/e2e.sh` with a scratch panel.
- lazy.nvim's module loader ignores a cleared `package.loaded` entry, so
  testing a branch inside the operator's config needs `dofile` (in
  `AGENTS.md`).
